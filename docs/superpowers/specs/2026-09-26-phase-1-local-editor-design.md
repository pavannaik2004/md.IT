# Phase 1 — Local editor: design

Date: 2026-09-26 · Status: awaiting review · Source: `PRD_v3_Technical_Markdown_Workspace (1).md` §5, §7, §13 (Phase 1)

## 1. Goal

A browser-only Markdown workspace in its own container. **Done when:** a user can create a project with folders and documents, edit Markdown with a live preview, reload the page, and find everything as they left it.

**In scope:** repo layout, frontend container (Nginx), CodeMirror 6 editor, live preview (markdown-it + DOMPurify), split / editor / preview modes, IndexedDB store (Dexie), project list, file tree with create / rename / duplicate / move / delete, autosave with save status, persistent-storage request and warning, light/dark theme, CI workflow for the frontend.

**Out of scope (later phases):** Mermaid, KaTeX, syntax highlighting, code-block styling, images (Phase 2); rendering settings, outline, stats, search, export/import, service worker (Phase 3); anything server-side (Phase 4+).

## 2. Decisions this spec depends on

Recorded with reasons in `decisions.md`:

- Design system ported to typed React components in `frontend/src/ui/` (not the global `window.MdIt` bundle).
- markdown-it as the Markdown pipeline.
- Plain React state + Dexie `useLiveQuery`; no global state library.
- npm; Vite; React 18; TypeScript strict; Vitest.
- Fonts self-hosted via Fontsource instead of Google Fonts.
- Sibling names unique; documents keep the `.md` extension in `title`.

## 4. Module boundaries

| Module | Owns | May import |
| --- | --- | --- |
| `ui/` | Design-system components and CSS | React only |
| `store/` | All IndexedDB access | Dexie |
| `renderer/` | Markdown → safe HTML | markdown-it, DOMPurify |
| `editor/` | CodeMirror instance and keymap | CodeMirror, `ui/` |
| `tree/` | Hierarchy UI and actions | `store/`, `ui/` |
| `app/` | Routing, layout, autosave wiring, save status | all of the above |

Rule: no module other than `store/` imports `dexie`. `renderer/` has no side effects and no imports from the app.

## 5. Design system usage

- `ui/tokens.css` generated by hand from the design system's `tokens.json`: all color tokens under `:root` (light) and `[data-theme="dark"]` plus `@media (prefers-color-scheme: dark) :root:not([data-theme="light"])`; spacing, radius, size, shadow, font families, `--doc-*` defaults.
- `ui/components.css` copied from the design system's `bundle.css`, minus the Google Fonts `@import`.
- Components ported for Phase 1: Wordmark, Icon, Button, IconButton, SegmentedControl, Menu, Input, TreeItem, SaveStatus, EmptyState, Prose, Callout, Badge, Kbd, Dialog. (CodeBlock, RangeField, VersionItem come with the phases that use them.)
- Rules from PRD §7.1 apply: tokens only, no hard-coded colors/sizes/fonts; visible focus ring; `prefers-reduced-motion` respected; voice (sentence case, verb-first, no emoji or exclamation marks; product name **md.IT**).

## 6. Data model (IndexedDB, Dexie schema version 1)

```ts
Project  { id, name, description, cloudProjectId?, createdAt, updatedAt }
Folder   { id, projectId, parentFolderId: string | null, name, createdAt, updatedAt }
Document { id, projectId, folderId: string | null, title, content,
           cloudDocumentId?, headVersionId?, dirty, createdAt, updatedAt }
ImageAsset { id, projectId, path, contentType, bytes: Blob, sha256 }   // unused until Phase 2
Setting  { key, value }
```

Indexes: `projects: id, updatedAt`; `folders: id, projectId, [projectId+parentFolderId]`; `documents: id, projectId, [projectId+folderId]`; `images: id, projectId, [projectId+path]`; `settings: key`.

Root-level items use `null` for parent. Because IndexedDB cannot index `null`, the stored value for "root" is the empty string `""`; the store API converts to and from `null` so callers never see `""`.

IDs: `crypto.randomUUID()`. `dirty` is set `true` on every content save (it means "changed since the last cloud version"; nothing clears it until Phase 5).

## 7. Store API

All functions are async and throw typed errors: `NotFoundError`, `NameConflictError`, `InvalidMoveError`, `ValidationError` (empty or `/`-containing names).

- **Projects:** `listProjects()`, `getProject(id)`, `createProject(name)`, `renameProject(id, name)`, `setProjectDescription(id, text)`, `deleteProject(id)` (cascade: folders, documents, images).
- **Folders:** `createFolder(projectId, parentFolderId, name)`, `renameFolder(id, name)`, `moveFolder(id, newParentId)` (rejects moving into itself or a descendant), `deleteFolder(id)` (cascade: descendant folders and their documents), `listFolders(projectId)`.
- **Documents:** `createDocument(projectId, folderId, title?)` (default "Untitled.md", then "Untitled 2.md", …), `renameDocument(id, title)` (appends `.md` if missing), `duplicateDocument(id)` ("X copy.md", "X copy 2.md", …), `moveDocument(id, folderId)`, `deleteDocument(id)`, `getDocument(id)`, `saveDocumentContent(id, content)`, `listDocuments(projectId)` (returns full rows including content; projects are small enough in Phase 1).
- **Settings:** `getSetting<T>(key, fallback)`, `setSetting(key, value)`.
- **Uniqueness:** among children of the same parent, folder names and document titles are unique, compared case-insensitively. A folder and a document may not share a name either.
- **Cascades** run in one Dexie `rw` transaction; any project mutation updates its `updatedAt`.

Reactive reads in components use `useLiveQuery(() => store.listX(...))` via thin hooks in `store/hooks.ts` (the only place `dexie-react-hooks` is imported).

## 8. Renderer

`render(markdown: string): string` — markdown-it (`html: true`, `linkify: true`, `typographer: false`) plus `markdown-it-task-lists`, then DOMPurify with its default HTML profile. Links get `rel="noopener noreferrer"` and `target="_blank"` for external URLs. On any exception it returns a single `<div class="md-render-error">` containing the escaped message. Pure; no DOM access except DOMPurify's.

## 9. Editor and autosave

- CodeMirror 6 with `@codemirror/lang-markdown` (GFM), history (undo/redo), line wrapping, a theme built from tokens (`--paper-raised` ground, `code-editor` type 14/24 Geist Mono, `accent` cursor, `accent-soft` selection).
- `Mod-s` bound in CodeMirror and on `window`: flush the save immediately and prevent the browser's save dialog.
- `useDocumentDraft(docId)` hook in `app/`:
  - loads content once per `docId`; editor is uncontrolled after load;
  - on change: update draft, schedule preview render (150 ms debounce) and save (1000 ms debounce);
  - status machine: `saved` → `saving` → `saved` | `failed`; a new edit after `failed` retries;
  - flush pending save on doc switch, unmount, and `beforeunload`/`visibilitychange=hidden`.
- SaveStatus copy: "Saved locally", "Saving…", "Couldn't save — your last changes are only in this tab".

## 10. Screens

**Project list (`/`):** toolbar with Wordmark; list of projects (name, description, document count, updated time) with Open / Rename / Edit description / Delete via Menu; "New project" primary Button; EmptyState when none ("No projects yet" / "Projects live in this browser. Create one to start writing."). Storage warning Callout (warning tone) unless dismissed: "Your work is saved in this browser. Clearing browser data deletes it." Dismissal stored in settings.

**Workspace (`/p/:projectId` and `/p/:projectId/d/:docId`):**
- Toolbar (44px): Wordmark (links to `/`), project name, mode SegmentedControl centered (Split / Editor / Preview, icons `columns` / `pencil` / `eye`), SaveStatus right, theme IconButton.
- Tree (264px, `paper-sunken`): header "Files" with IconButtons "New document" and "New folder"; rows as TreeItem, indented by depth, folders open/closed (open state in memory); active document highlighted; "more" Menu per row: Rename, Duplicate (documents), New document / New folder (folders), Move to…, Delete. EmptyState when the project is empty.
- Rename is inline (Input replaces the row; Enter saves, Escape cancels; errors shown as hint).
- Delete opens a danger Dialog naming what goes with it ("Delete “Notes” and the 4 documents inside it? This can't be undone.").
- Move to… opens a Dialog listing valid destination folders (root + folders not inside the item).
- Drag-and-drop: drag documents/folders onto folders or the root area; invalid targets are not highlighted.
- Main area: editor and preview 50/50 with one `line` divider; preview wraps output in `Prose`. With no document open: EmptyState "Open a document from the tree, or create one."
- Mode is stored in settings (`ui.mode`); theme stored in settings (`ui.theme`: `system` | `light` | `dark`) and applied as `data-theme` on `<html>`.

## 11. Storage safety

On app start: if `navigator.storage?.persist` exists and `persisted()` is false, call `persist()`. Result stored in state; the warning Callout shows regardless of the result until dismissed (clearing browser data deletes even persisted storage).

## 12. Container and CI

- `frontend/Dockerfile`: stage 1 `node:22-alpine`, `npm ci && npm run build`; stage 2 `nginx:1.27-alpine` with `nginx.conf` and `dist/`. Exposes 80.
- `nginx.conf`: `try_files $uri /index.html`; long cache for hashed `/assets/*`, `no-cache` for `index.html`; headers: `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: https:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.
- `.github/workflows/ci.yml` on pull_request (path filter `frontend/**`): `npm ci`, `npm run lint`, `npm run typecheck`, `npm test -- --run`, `npm run build`, `docker build frontend` (no push).

## 13. Testing

TDD for store, renderer, and hooks; component tests for key flows.

- Store (Vitest + `fake-indexeddb`): CRUD for each entity; uniqueness and `NameConflictError`; default and duplicate naming; cascade deletes; `InvalidMoveError` for folder cycles; root `null` ⇄ `""` mapping; settings round-trip.
- Renderer: GFM (headings, tables, task lists, strikethrough, autolinks); XSS payloads (`<script>`, `onerror=`, `javascript:` links) stripped; error path returns the error block.
- `useDocumentDraft` (fake timers): debounce timing, status transitions, flush on unmount, failure then retry.
- Components (Testing Library): create project from empty state; create/rename/delete document in tree; delete confirmation lists cascade.
- Manual check before completion: `docker build` + run the container, create a project, reload, verify persistence.

## 14. Acceptance

1. `npm run lint`, `typecheck`, `test`, `build` pass in `frontend/`.
2. `docker build -t mdit-frontend frontend && docker run -p 8080:80 mdit-frontend` serves the app.
3. In that container: create project → folders → documents, type Markdown, see preview update, reload, everything persists; switch modes; delete cascades after confirmation.
4. No module except `store/` imports `dexie`.
