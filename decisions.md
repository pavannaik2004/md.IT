# Decisions

Every decision taken while building md.IT, newest last. Each entry: what, why, alternatives considered. PRD open decisions (D1–D8) keep their PRD IDs; project decisions use `P-NNN`.

| ID | Date | Decision | Why | Alternatives considered |
| --- | --- | --- | --- | --- |
| P-001 | 2026-09-26 | Build in phase-sized cycles (spec → plan → build), starting with PRD Phase 1 only | One spec for all 8 phases would be huge and go stale; each phase is independently useful | Phases 1–3 in one cycle; Phases 1 + 4 together |
| P-002 | 2026-09-26 | Git flow: feature branch per cycle (e.g. `phase-1-local-editor`), pushed and opened as a PR; `main` only changes by merge | Matches PRD CI-on-PR / deploy-on-merge model; keeps `main` clean | Commit to `main` directly; commit locally only |
| P-003 | 2026-09-26 | Port the md.IT design system into typed React components under `frontend/src/ui/`; `tokens.css` built from `tokens.json`, component CSS from `bundle.css` | Typed, tree-shaken, testable; stays close to the source so changes can flow back to the design system | Vendor `bundle.js` as global `window.MdIt`; separate workspace package (YAGNI with one consumer) |
| P-004 | 2026-09-26 | Markdown pipeline: markdown-it | Synchronous and fast for live preview; mature plugins (KaTeX, task lists); token stream serves outline/stats; custom image-attribute rule is small | remark/unified (async, heavier) |
| P-005 | 2026-09-26 | State: React state + Dexie `useLiveQuery`; no Redux/Zustand | Store is the source of truth; live queries keep UI in sync without a second cache | Zustand, Redux Toolkit |
| P-006 | 2026-09-26 | Tooling: npm, Vite, React 18, TypeScript strict, Vitest + Testing Library + fake-indexeddb, ESLint | npm already installed; single JS package; Vite/Vitest share config | pnpm; Jest |
| P-007 | 2026-09-26 | Self-host Geist, Geist Mono, Source Serif 4 via Fontsource (deviation from design system's Google Fonts `@import`) | App must work offline; CSP stays `'self'`; exports (Phase 3) can embed the same files | Google Fonts at runtime |
| P-008 | 2026-09-26 | Names unique among siblings (case-insensitive, folders and documents together); documents keep `.md` in `title` | Zip export paths and relative image paths (Phases 2–3) must not collide; tree shows real filenames | Allow duplicates and disambiguate at export time |
| P-009 | 2026-09-26 | Root-level parent stored as `""` in IndexedDB, exposed as `null` by the store API | IndexedDB cannot index `null`; compound index `[projectId+parentFolderId]` needs a value | Separate `isRoot` flag; unindexed filter |
| P-010 | 2026-09-26 | Service worker for offline reload deferred to Phase 3 (`vite-plugin-pwa`) | PRD lists no phase for it; Phase 1 data already works offline once loaded | Add in Phase 1 |
| P-011 | 2026-09-26 | Theme: follows `prefers-color-scheme`, manual override (`system`/`light`/`dark`) stored in settings, applied as `data-theme` on `<html>` | Design system defines both themes with shared token names | Light only |
| P-012 | 2026-09-26 | Routing: React Router 7 via the `react-router` package (`BrowserRouter` + `Routes`); routes `/`, `/p/:projectId`, `/p/:projectId/d/:docId` | v7 merged `react-router-dom` into `react-router`; declarative routes are enough for 3 screens | Data routers (`createBrowserRouter`); hash routing |
| P-013 | 2026-09-26 | App-side design-system extensions, to be upstreamed to the design system artifact: `Input.error`; `TreeItem` `trailing`/`dropTarget`/always-tabbable/`aria-label`; `IconButton` ref forwarding; new `MenuButton` (fixed-position popover); `Dialog` Escape-to-close, initial focus, focus restore; `SegmentedControl` controlled-only; `Input` renders a separate `<label>` (not a wrapping one) so hint/error text stays out of the accessible name; Phase 2: `--syntax-*` tokens (light and dark) and `.md-code .hljs-*` colors, `TreeItem` image thumbnail popover (`.tree-thumb`); CSS in the "app extensions" block of `ui/components.css` | PRD §7.1 says add to the design system first; the artifact is edited outside the repo, so extensions are listed here and marked in code until synced | Block Phase 1 on editing the artifact first |
| P-014 | 2026-09-26 | TypeScript `~6.0.3` (not 7.x) | typescript-eslint 8.70 supports `<6.1.0` | TS 7 without type-aware lint |
| P-015 | 2026-09-26 | Font tokens list Fontsource family names first (`"Geist Variable"`, `"Geist Mono Variable"`, `"Source Serif 4 Variable"`), then the design-system names | Fontsource variable packages register those family names | Rename @font-face rules by hand |
| P-016 | 2026-09-26 | Shared dialogs live in `src/dialogs/` (may import `ui/` and `store/` for error text) | Used by both `app/` and `tree/`; keeps `ui/` free of store knowledge and avoids tree → app imports | Put them in `ui/`; duplicate per screen |
| P-017 | 2026-09-26 | Store conventions: document type named `MdDocument` (avoids DOM `Document`); `get*` returns `null` when missing, mutations throw typed `StoreError`s whose messages are UI-ready; timestamps are ms numbers; `npm test` runs `vitest run` | Clear loading/missing distinction for live queries; one place for user-facing error text | Throw on get; `Date` objects |
| P-018 | 2026-09-26 | Frontend image base `nginx:1.28-alpine` (current stable line), app image built from `node:22-alpine` | Pinned, stable, small; tag verified to exist | `nginx:stable-alpine` (moving tag), 1.29 mainline |
| P-019 | 2026-09-26 | jsdom `^29` for tests instead of 30 | jsdom 30 requires Node ≥22.22.2; this machine has 22.20.0 and 29 supports ≥22.13 | Upgrade local Node (can revisit; CI's Node 22 is newer) |
| P-020 | 2026-09-26 | Rendered documents drop inline `style` attributes and `<style>` blocks (DOMPurify `FORBID_ATTR: ['style']`, `FORBID_TAGS: ['style']`; tags added after final review) | `style` can carry `url(javascript:…)` and would override the workspace rendering settings (PRD §5.6) | Keep `style` and rely on DOMPurify's default CSS handling |
| P-021 | 2026-09-26 | IDs come from `store/ids.ts` `newId()`: `crypto.randomUUID` when present, otherwise a v4 UUID from `crypto.getRandomValues` | `randomUUID` exists only on secure pages; the self-hosted container opened over plain HTTP on a LAN address could not create anything (final review) | Require HTTPS |
| P-022 | 2026-09-26 | Autosave keeps the last unconfirmed content per document: Ctrl/Cmd+S retries it after a failure, and the browser asks before leaving while it is unconfirmed | Final review found a failed save could not be retried and closing the tab could lose it | Retry only on the next edit (original design) |
| P-023 | 2026-09-26 | Images are files in the tree: stored per folder, same sibling-name rules and rename/move/delete as documents; clicking an image row does not navigate (menu offers Insert in document; hover shows a thumbnail) | Relative paths then mean the same thing in the app, on disk and in the Phase 3 zip; one set of tree behaviours | Separate flat image library dialog; hidden assets with no management UI |
| P-024 | 2026-09-26 | Image rows store `folderId` + `name` instead of the PRD's `path`; bytes live in a separate `imageData` table as `ArrayBuffer` (Dexie schema v2) | A stored path would need rewriting on every folder rename/move; `fake-indexeddb` under jsdom can't round-trip `Blob` (probe) but can `ArrayBuffer`; keeping bytes out of `images` keeps tree live queries light | `path` column; `Blob` in the `images` row |
| P-025 | 2026-09-26 | Two-stage rendering: pure synchronous `render(markdown, context)` sanitizes user HTML, then splices trusted KaTeX output at per-render nonce placeholders; the preview's DOM pass renders Mermaid (lazy chunk, strict, cached by theme+source), copy buttons and link clicks | KaTeX and Mermaid output depend on inline styles that P-020 strips; nonces stop documents forging trusted output; Mermaid can't run in jsdom and is ~2 MB | Fully async `render()`; allowing `style` on KaTeX/Mermaid classes (forgeable) |
| P-026 | 2026-09-26 | Libraries: highlight.js core with the 9 PRD languages (no auto-detect); KaTeX 0.18 via an in-house `$`/`$$` rule; in-house `{width align}` image rule; Mermaid 11.17.x; `@noble/hashes` for SHA-256 | highlight.js is sync and class-based (token colors); texmath is unmaintained and the VS Code plugin pins KaTeX 0.16; markdown-it-attrs allows arbitrary attributes; Mermaid 12.0 is two weeks old; `crypto.subtle` is missing over plain HTTP | Shiki; markdown-it-texmath; @vscode/markdown-it-katex; markdown-it-attrs; Mermaid 12 |
| P-027 | 2026-09-26 | Relative `.md` links in the preview open the document in the workspace; missing targets and other relative links show a notice instead of navigating the browser away | Fixes a deferred Phase 1 minor using the same path resolver as images | Leave for a later phase |
